# Loom interaction contracts

The TypeScript contracts in `src/contracts` own command and result shapes. Project lifecycle and file recovery live in `src/services/project`; agent execution and permissions live in `src/services/agents`. UI behavior follows those boundaries.

| Capability     | Canonical owner                                        | Source of truth                           | Allowed variants                                                                                                                                                                                  | Verification                                               |
| -------------- | ------------------------------------------------------ | ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| Select/Listbox | Native HTML select                                     | This contract and the named runtime owner | Native platform popup and keyboard behavior are intentional for existing settings and question controls.                                                                                          | Existing Electron settings and question tests              |
| CRUD           | Project service and ProjectManager/ProjectPanel        | This contract and the named runtime owner | Named confirmation before deletion. Individual files retain Loom recovery. Entire project folders use system Trash; failure preserves the library entry.                                          | Project library unit tests and Electron project/file tests |
| Dialogs        | Modal in primitives.tsx                                | This contract and the named runtime owner | Native dialog with focus containment, Escape, and focus return. Destructive confirmation initially focuses Cancel.                                                                                | Electron deletion cancellation and keyboard tests          |
| Menus          | ActionMenu.tsx                                         | This contract and the named runtime owner | Native popover, arrow-key navigation, Escape, and trigger focus return.                                                                                                                           | Electron file menu tests                                   |
| Feedback       | Existing workspace notices and inline operation errors | This contract and the named runtime owner | Persist actionable errors at the affected operation; preserve draft input on failure.                                                                                                             | Electron agent recovery and PDF tests                      |
| Scrollbar      | tokens.css and workspace.css                           | This contract and the named runtime owner | Application scroll regions inherit visible theme-aware scrollbars.                                                                                                                                | Existing appearance tests                                  |
| Agent recovery | AgentService and AgentComposer                         | This contract and the named runtime owner | Temporary restore failures retry the existing chat. Confirmed missing chats can continue with retained local history. Recovery never resends an earlier request.                                  | Agent reconnect unit tests and Electron agent tests        |
| PDF repair     | BuildFeedback and Workspace                            | This contract and the named runtime owner | Ask agent to fix prepares an editable request, preserves existing draft, and focuses the composer. Sending attaches authoritative diagnostics. Active agent work disables another repair request. | Electron diagnostic-context test                           |

Project deletion follows the user's request to delete both project files and entire projects. System Trash is used for folders so deletion does not permanently erase their contents. Native agent permission prompts continue to own approval for agent actions.
